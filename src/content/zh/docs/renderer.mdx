Velox 用 Skia 光栅化。有 GPU 路径，但它是可选且未完成的。默认发布的是 CPU。

<Callout type="note" title="不是要道歉的限制">
CPU 光栅化是**刻意的默认值**: 它使金图测试确定性、保持构建无 EGL 和窗口系统依赖、并在无头 CI 机器上完全相同地运行。GPU 渲染是一个配置标志，不是架构承诺。
</Callout>

## 为什么是 CPU?

1. **确定性输出** — 相同输入 == 相同像素，到处如此。无 GPU 驱动变体。
2. **无头 CI 友好** — 无需 EGL/GBM/Wayland/X11 运行时。在服务器上直接跑。
3. **最小依赖** — 只有 `skia-safe` (静态链接)。无 `wgpu`/`glow`/`ash` 链。
4. **清晰的性能模型** — 你知道你在得到什么。无惊喜 GPU 降频。

## 渲染管线 (每帧)

```
┌─────────────┐
│  信号变化   │  ──►  脏检查
└──────┬──────┘
       ▼
┌─────────────┐
│  render()   │  ──►  新鲜 VNode 树 (内联子组件)
│  调用       │
└──────┬──────┘
       ▼
┌─────────────┐
│  计算布局   │  ──►  块 + Flex 布局
│             │       几何 (velox-dom)
└──────┬──────┘
       ▼
┌─────────────┐
│  计算样式   │  ──►  选择器匹配 + 级联
│             │       解析 (velox-style)
└──────┬──────┘
       ▼
┌─────────────┐
│  Skia 光栅  │  ──►  复用表面光栅化
│             │       呈现
└─────────────┘
```

**每个阶段每帧从零运行。** 没有东西与上一帧 diff。无保留树。

## 表面复用

渲染器缓冲一个 `skia_surface::Surface`。如果视口尺寸变化，它重新分配；否则复用。避免分配抖动。

## GPU 路径 (实验性)

```bash
velox build --features gpu
```

它使用 `wgpu` + `skia-safe` 的 GPU 后端。它不是默认因为:
- 驱动崩溃使测试不稳定
- CI 中表现不佳
- 并非所有平台都有完整特性平权

## 性能备注

| 指标 | 典型范围 |
| --- | --- |
| 帧时间 (CPU, 1080p, 简单 UI) | 1-3 ms |
| 内存 (表面 + 缓冲) | 15-30 MB |
| 构建大小 (仅 CPU) | ~4 MB stripped |

如果你的 UI 跑不满 60 FPS，看 `velox_renderer::present` 的 profiler — 通常是布局或文本换行，不是光栅化。
