Velox হলো Rust-এর জন্য একটি UI ফ্রেমওয়ার্ক। এটি এক-ফাইল কম্পোনেন্টকে Rust
কোডে কম্পাইল করে, একটি সত্যিকারের লেআউট ইঞ্জিন চালায়, CSS ক্যাসকেড
সমাধান করে, এবং Skia-র মাধ্যমে আপনার নিজের উইন্ডোতে ফলাফল রাস্টারাইজ করে।

এখানে DOM নেই, ব্রাউজারও নেই। এই বাক্যটি কোনো মার্কেটিং
অবস্থান নয় — এটিই কারণ কিছু জিনিস যেভাবে কাজ করে, আর কয়েকটি
জিনিস DOM-এর চেয়ে সহজ, আর কয়েকটি কঠিন।

<Callout type="note" title="এই ডকুমেন্টেশন যা করবে না">
Velox এখনও স্থিতিশীল হওয়ার পর্যায়ে। এই সাইটি কোড দিয়ে যাচাই করা
আজকের আচরণই বর্ণনা করে, রোডম্যাপের পরিকল্পনা নয়। কোথাও কিছু
পরিকল্পিত কিন্তু বাস্তবায়িত না হলে সেটি সেই শব্দেই লেখা আছে।
[রোডম্যাপ পেজ](/bn/docs/roadmap) সব এমন ক্ষেত্র এক জায়গায় সংগ্রহ করে।
</Callout>

## প্রথমে বোঝার মতো একটি বিষয়

বেশিরভাগ ফ্রেমওয়ার্ক state বদলালে নোডের একটি tree ধরে রাখে এবং সেটি
প্যাচ করে। Velox তা করে না। রেন্ডার লুপ **ইমিডিয়েট-মোড**:

1. একটি সিগন্যাল বদলায়।
2. জেনারেট করা `render()` ফাঙ্কশন আবার চলে এবং শূন্য থেকে **সম্পূর্ণ নতুন**
   `VNode` tree তৈরি করে।
3. সেই নতুন tree-এর উপর লেআউট চলে।
4. Skia সেটি আঁকে।

এরপর কোনো ধাপ নেই যা নতুন tree আগেরটির সাথে তুলনা করে। কিছু
তুলনা করার দরকারই নেই, কারণ কিছুই রাখা হয়নি।

<Callout type="warning" title="এটি বিনামূল্যে নয়, এবং এটি বাগ নয়">
প্রতি ফ্রেমে সবকিছু হিসাব করা মানে সেই কাজটি হয় যা retained tree
এড়িয়ে যেত। বিনিময়ে আপনি পাবেন কোনো stale state নেই, কোনো
memoisation বই নেই, "এটা রি-রেন্ডার কেন হলো" ধরনের ডিবাগিং নেই, এবং
সত্যিই ছোট একটি codebase। এটি আপনার জন্য সঠিক সুযোগ কি না নির্ভর করে
আপনি কী বানাচ্ছেন তার উপর — [রেন্ডারার পেজ](/bn/docs/renderer) সৎভাবে
পারফরম্যান্সের বৈশিষ্ট্য ব্যাখ্যা করে।
</Callout>

একটি reconciler এখানে একসময় ছিল। সেটি সরানো হয়েছে, এবং কারণটি
প্রকল্পের নিজস্ব `docs/RECONCILER.md`-তে লেখা আছে: key মিললে এটি আগের
ফ্রেমের নোড ফেরত দিত এবং নতুন কনটেন্ট বাদ দিত, ফলে যে keyed child-এর
টেক্সট বদলেছিল সেটি stale টেক্সটই দেখাত। সেটি ঠিক করার বদলে লুপটিকে
সৎভাবে ইমিডিয়েট-মোড করা হয়েছে।

## একটি ফ্রেমের প্রকৃত খরচ

নিচের পাঁচটি ধাপই পুরো পাইপলাইন। বাকি সবকিছু এই ডকুমেন্টেশনে এই
পাঁচটির অন্যতম বিশদ।

## ক্রেটগুলো

Velox হলো ছয়টি স্বাধীন ক্রেট, প্রতিটির নিজস্ব `Cargo.toml` ও নিজস্ব
টেস্ট। আপনি শুধু `velox-style` দরকার হলে সেটিই ব্যবহার করতে পারেন।

| ক্রেট | কী করে |
| --- | --- |
| `velox-core` | সিগন্যাল, ইফেক্ট, computed ভ্যালু, ওয়াচার, lifecycle হুক |
| `velox-sfc` | `.vx` ফাইল পার্স করে Rust জেনারেট করে |
| `velox-dom` | `VNode`, লেআউট ইঞ্জিন, স্টাইল সমাধান |
| `velox-style` | CSS পার্সিং, সিলেক্টর, ক্যাসকেড |
| `velox-renderer` | Skia ব্যাকএন্ড, পেইন্টিং, হিট টেস্টিং, ইভেন্ট লুপ |
| `velox-cli` | `init`, `build`, `dev`, `run`, `lint`, `add` |

নির্ভরতার দিক কঠোরভাবে নিচের দিকে: রেন্ডারার DOM-কে নির্ভর করে, DOM
স্টাইলকে, স্টাইল core-কে। কেউ CLI-এর উপর নির্ভর করে না।
[আর্কিটেকচার পেজ](/bn/docs/architecture) সীমানাগুলো বিস্তারিতে দেখায়।

## শুরু করার আগে জানার দরকার তিনটি সীমাবদ্ধতা

<Callout type="danger" title="ইভেন্ট: ঠিক তিনটি">
Velox তিনটি রানটাইম ইভেন্ট চ্যানেল তারি: `on:click`, `on:click-payload` এবং
`on:input`। এখনও কোনো সাধারণ keybinding সিস্টেম নেই, এবং `change`,
`mouseover` বা `keydown` নেই। এই সাইটির আগের খসড়ায় সবগুলো ছিল; সেটি
ফ্রেমওয়ার্ক-নিরপেক্ষ README থেকে নকল করা হয়েছিল এবং ভুল ছিল।
[ইভেন্ট](/bn/docs/events) দেখুন।
</Callout>

<Callout type="danger" title="ক্যাসকেড: শেষ ম্যাচ জেতে">
CSS specificity নেই এবং `!important` নেই। নিয়ম সোর্স অর্ডারে প্রযোজ্য,
এবং কোনো প্রপার্টির জন্য শেষ ম্যাচ করা নিয়মই জেতে। এতে **ক্রমই** পুরো
ওভাররাইড মেকানিজম — যা ঠিক আছে, যদি আপনি শুরু করার আগে জেনে নেন।
</Callout>

<Callout type="danger" title="ডার্ক মোড: আপনিই বানাবেন">
`prefers-color-scheme` নেই এবং `var()` নেই। থিম হলো root এলিমেন্টে একটি
ক্লাস এবং সাধারণ রঙের মান। এটি ইমিডিয়েট-মোড tree-র একটি পরিণতি:
কাস্টম প্রপার্টি যেন কোনো স্টাইল-ইনহেরিটেন্স স্টেপের মধ্য দিয়ে যেতে পারে,
এমন কোনো স্টেপ নেই।
</Callout>
