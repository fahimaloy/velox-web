`velox-sfc` ঠিক কী পার্স করে তার সঠিক তালিকা। কোন ডিরেক্টিভ বাস্তবায়িত
হিসেবে চিহ্নিত নয়, সেটিও পার্স হয় এবং লিন্ট পরিষ্কার — কোনটি কী, সেটাই
এই পেজের উদ্দেশ্য।

## ডিরেক্টিভ

| ডিরেক্টিভ | বাস্তবায়িত | নোট |
| --- | :---: | --- |
| `v-if` | হ্যাঁ | |
| `v-else-if` | হ্যাঁ | অবশ্যই `v-if`-এর সরাসরি পরে |
| `v-else` | হ্যাঁ | অবশ্যই `v-if`/`v-else-if`-এর পরে |
| `v-for` | হ্যাঁ | প্রতি পুনরাবৃত্তিতে এলিমেন্ট ক্লোন করে |
| `v-show` | হ্যাঁ | `display` টগল করে, নোড থাকে |
| `v-model` | **না** | পার্স হয়, লিন্ট পরিষ্কার, কিছু করে না |
| `v-slot` | **না** | ব্যাকরণে নেই |

## অ্যাট্রিবিউটের ধরন

| প্রিফিক্স | অর্থ | উদাহরণ |
| --- | --- | --- |
| কিছু নয় | স্ট্যাটিক টেক্সট | `type="text"` |
| `:` | State এক্সপ্রেশনে বাইন্ড | `:value="name()"` |
| `@` | ইভেন্ট হ্যান্ডলারের নাম | `@click="increment"` |
| `v-` | ডিরেক্টিভ | `v-if="ok()"` |

<Callout type="note" title="বাইন্ড অ্যাট্রিবিউট স্ট্রিং-বানানো হয়">
`:foo="bar"` বেরিয়ে আসে `foo="<to_string(bar)>"`। এটি টাইপড মান নয়।
</Callout>

## শর্তাবলি চেইন

```html
<button v-if="f() == 'a'">A</button>
<button v-else-if="f() == 'b'">B</button>
<button v-else>C</button>
```

<Callout type="warning" title="অ্যাডজাসেন্সি কাঠামোগতভাবে সমাধান হয়">
চেইনটি পার্স করা টেমপ্লেটে সিবলিং অ্যাডজাসেন্সি দিয়ে মেলানো হয়। ব্রাঞ্চগুলোর
মাঝে কমেন্ট নোড বা নন-হোয়াইটস্পেস টেক্সট থাকলে চেইন ভেঙে যায় এবং
ফলাফল হয় সব ব্রাঞ্চই রেন্ডার হওয়া।
</Callout>

## স্টাইল

| রূপ | প্রভাব |
| --- | --- |

| `<style scoped>` | প্রতিটি কম্পাউন্ডে `[data-v-<hash>]` |

<Callout type="danger" title="দ্বিতীয় স্টাইল ব্লক প্রথমটি নীরবে প্রতিস্থাপন করে">
একটি ফাইলে দুটি `<style>` ব্লক মিলে যায় না। দ্বিতীয়টি প্রথমটি বদলে দেয়,
কোনো সতর্কতা ছাড়া। একটি ব্লকই রাখুন।
</Callout>
